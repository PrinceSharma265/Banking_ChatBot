## Overview

Banking Support Chatbot is an AI-powered banking support assistant built with a Retrieval-Augmented Generation (RAG) pipeline. It helps users answer banking queries using indexed banking documents, delivers accurate responses via Groq LLM, and supports PDF/TXT upload for expanding knowledge coverage.

## Tech Stack

- **Backend:** FastAPI (Python)
- **LLM:** Groq API (Llama 3.1)
- **Embeddings:** sentence-transformers (`all-MiniLM-L6-v2`)
- **Vector Database:** ChromaDB
- **Frontend:** HTML, CSS, JavaScript
- **Deployment:** Railway

## Features

- Conversational chat interface
- RAG pipeline for accurate, context-aware answers
- PDF and TXT document upload support
- Session-based context retention
- Banking data coverage including loans, credit cards, FAQs, RBI guidelines

## API Endpoints

- `GET /health` - Check server status
- `POST /chat` - Send a message and receive a response
- `POST /upload` - Upload PDF or TXT documents for indexing

## Architecture

### System Components

The Banking Support Chatbot follows a RAG 
(Retrieval-Augmented Generation) architecture 
with these components:

#### Frontend (frontend/index.html)
- Single page HTML CSS JavaScript application
- Chat interface with streaming response support
- File upload for PDF and TXT documents
- Session ID generated on page load for conversation tracking
- Connects to FastAPI backend via REST API calls

#### Backend (backend/main.py)
- FastAPI Python web framework
- Three API endpoints: GET /health, POST /chat, POST /chat/stream, POST /upload
- In-memory session management storing last 10 messages per session
- CORS middleware enabled for frontend communication
- PDF parsing using pypdf library
- Text chunking with 500 character size and 100 character overlap

#### RAG Pipeline (backend/rag_pipeline.py)
- Retrieves top 5 relevant chunks from ChromaDB for each query
- Builds optimized system prompt with retrieved context
- Sends prompt to Groq LLM API
- Supports both regular and streaming response modes
- Falls back to error message if API fails

#### Vector Database (backend/vector_store.py)
- ChromaDB persistent local vector storage
- Lazy loading to prevent startup timeout
- Stores document embeddings generated by sentence-transformers
- Performs cosine similarity search to find relevant chunks
- Returns top N most similar chunks for context injection

#### Embedding Model
- Model: all-MiniLM-L6-v2 from sentence-transformers
- Runs completely locally - no API key required
- Converts text chunks and queries into 384-dimensional vectors
- Same model used for both document indexing and query embedding

#### LLM (Groq API)
- Model: Llama 3.1 8B Instant
- Free tier API with fast inference
- Receives system prompt + context + chat history + user query
- Generates context-aware banking responses
- Streaming mode sends tokens as they are generated

#### Banking Knowledge Base (backend/data/)
- loan_policy.txt: Personal, home, vehicle and education loan policies
- credit_card_guide.txt: Card types, fees, rewards and eligibility
- banking_faq.txt: Account opening, KYC, NEFT, RTGS, UPI, ATM, FD
- rbi_guidelines.txt: Repo rate, KYC norms, digital lending, ombudsman

### RAG Flow

Step 1: User types a question in the chat interface
Step 2: Frontend sends POST request to /chat/stream endpoint
Step 3: Backend calls search() function in vector_store.py
Step 4: Query is converted to embedding using sentence-transformers
Step 5: ChromaDB performs similarity search and returns top 5 chunks
Step 6: Chunks are joined into context string
Step 7: Context + chat history + query sent to Groq LLM
Step 8: Groq streams response tokens back to backend
Step 9: Backend streams tokens to frontend in real time
Step 10: Frontend displays tokens word by word as they arrive

- Backend deployed on Railway cloud platform
- Auto-deploys when code is pushed to GitHub main branch (CI/CD)
- Frontend served as static HTML file
- Environment variables stored securely in Railway dashboard

## Setup Instructions

### Prerequisites
- Python 3.11 or higher
- Git installed
- Groq API key (free at https://console.groq.com)

### Step 1 - Clone the Repository
```bash
git clone https://github.com/PrinceSharma265/Banking_ChatBot.git
cd Banking_ChatBot
```

### Step 2 - Create Virtual Environment
```bash
cd backend
python -m venv venv
```

Activate on Windows:
```bash
venv\Scripts\activate
```

Activate on Mac/Linux:
```bash
source venv/bin/activate
```

### Step 3 - Install Dependencies
```bash
pip install -r requirements.txt
```

### Step 4 - Configure Environment Variables
Create a `.env` file inside the backend/ folder:
```text
GROQ_API_KEY=your_groq_api_key_here
```

Never share or commit your `.env` file.
It is already added to `.gitignore` for safety.

### Step 5 - Ingest Banking Documents
```bash
python ingest.py
```

This will:
- Read all 4 banking documents from data/ folder
- Split them into 500 character chunks
- Generate embeddings using sentence-transformers
- Store 106 chunks in ChromaDB vector database

### Step 6 - Start the Backend Server
```bash
uvicorn main:app --reload --port 8000
```

Server will start at http://localhost:8000
Test it at http://localhost:8000/health

### Step 7 - Open Frontend
Open `frontend/index.html` in your browser.
Make sure `BACKEND_URL` in `index.html` points to:
```js
const BACKEND_URL = "http://localhost:8000";
```
